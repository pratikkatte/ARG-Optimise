# GFlowNet 1 MB VCF / 100 kb Benchmark

Date: 2026-08-01 PDT

## Scope

This benchmark validates a representative end-to-end local-refinement training
run for:

- VCF input size up to and including 1,000,000 uncompressed bytes.
- A half-open local refinement interval up to and including 100,000 bp.
- A single NVIDIA RTX A5500 GPU with 24 GB class VRAM.

The exact-size VCF benchmark input is generated by metadata-padding the existing
validated `validation/vcf/sim_l1mb_0.vcf` fixture. The padding is inserted before
`#CHROM`, so all sample columns, variant records, genotypes, coordinates, and
source-ARG compatibility are preserved.

## Reproducible Command

```bash
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
python benchmark_gflownet_workflow.py \
  --config config/config_1mb.yaml \
  --output-dir runs/benchmark_1mb_region_view_gpu_e2e \
  --epochs 1 \
  --device cuda \
  --deterministic \
  --inference-args 1 \
  --pad-vcf-to-bytes 1000000
```

The run writes:

- `runs/benchmark_1mb_region_view_gpu_e2e/benchmark_report.json`
- `runs/benchmark_1mb_region_view_gpu_e2e/checkpoints/best.pt`
- `runs/benchmark_1mb_region_view_gpu_e2e/inference/region_000001/arg_000001.trees`
- `runs/benchmark_1mb_region_view_gpu_e2e/sim_l1mb_0.padded_1000000b.vcf`

The report includes `region_vcf_views`, which records the exact local VCF
partition for each refinement request: whole-VCF variant count, target-region
variant count, cached exterior variant count, endpoint partial-row count, and
the cached outside-region log likelihood.

## Bottlenecks And Changes

The old failures occurred during gradient backpropagation after local rollouts.
The logs show the live batch of terminal trajectories was the practical memory
bottleneck, not VCF parsing, preprocessing, model initialization, or
checkpointing.

Changes made:

- Added explicit VCF input-size validation at 1,000,000 uncompressed bytes.
- Added explicit local refinement span validation at 100,000 bp, inclusive.
- Validated training batch size and gradient accumulation instead of silently
  normalizing invalid values.
- Updated the 1 MB local-refinement config to use `batch_size: 1` and
  `grad_accum_steps: 16`, preserving an effective batch of 16 while reducing
  live rollout memory.
- Added `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` in `train.sbatch` to
  reduce allocator-fragmentation risk.
- Added `benchmark_gflownet_workflow.py` to measure VCF parsing,
  preprocessing, local-refinement preparation, model initialization, training,
  checkpointing, and local-refinement inference with command, seed, config, git
  state, environment, CPU RSS, CUDA allocator peaks, and `nvidia-smi` memory.
- Made the region-local VCF view explicit so target-region variants are the only
  VCF rows carried by local rollout lineages, while outside-region variants are
  cached as a fixed whole-VCF likelihood contribution.

No variants are truncated, no records are skipped, and the requested refinement
region is not reduced.

## Limitations

- The measured acceptance run is a one-epoch deterministic smoke benchmark, not
  a full 3,000-epoch convergence or output-quality study.
- The exact 1 MB VCF uses metadata padding to exercise the file-size limit while
  preserving the validated source variants. Runtime and model memory will still
  scale with retained variant count and local trajectory complexity.
- CUDA determinism is requested, but PyTorch warns that memory-efficient
  attention backward can use a nondeterministic kernel in this environment.
- Inputs larger than 1,000,000 uncompressed VCF bytes or local refinement spans
  larger than 100,000 bp now fail with clear errors unless those limits are
  explicitly raised after separate profiling.

## Confirmation

The target representative workload is supported on the RTX A5500 with large
safety headroom: peak CUDA reserved memory was 0.230 GiB versus 23.5766 GiB
reported by PyTorch for the device.
